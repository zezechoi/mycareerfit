# Career FIT OS — 변경 이력

> 최초 기획서(`career_fit_prompt.md`) 대비 현재 구현까지의 변경사항.
> 1차 출처: 3주차 미션 회고(`3주차 미션 Career FIT OS.md`, 최지예 작성).

## 변하지 않은 핵심 (정체성)

- **철학** — 나도 회사를 고른다 · 서로 맞아야 오래간다 · 최종 결정은 내가 한다
- **패스해도 지원 가능** — 판정이 부정적이어도 사용자가 진행 선택 가능
- **이력서 1회 입력 → 이후 공고만** — 온보딩 1회, 반복은 공고만
- **각자의 기준** — 판단 기준(직무·환경·성장)은 사용자별로 온보딩에서 생성·수정 (2026-05 이후. 그 전엔 제작자 1인용·K-뷰티 기준 고정이었음)

## 주요 변경사항 (시간순)

### 1. 첫 구현 — 전부 "보류" 판정 문제
공고를 넣으면 다 "보류"가 떴음. 원인은 판단 기준이 틀렸던 것.
"브랜드 기획 직무냐"로 잡혀 있었는데 본인 경력과 안 맞는 기준이었음.
→ 더 근본 문제 발견: 판단 도구 전에 판단 기준이 먼저였다.

### 2. 기준 재설정 — 본인 분석부터 다시
해외영업 6년 + IT 마케터 1년, 화장품 경력 없음을 기준으로
온보딩 판단 기준을 4개로 교체.

### 3. 핵심 기준 4개 → 3개 통합
실제로 쓰면서 직무 적합 / 환경 적합 / 성장 적합 3개로 통합·정교화.
(기존 2·4번이 "브랜드 전체 흐름"으로 중복됐던 것을 해소)
네이밍도 "4대 기준 체크" → "핵심 기준 체크".

### 4. 화장품 경력 필수 감지 추가
화장품 경력이 없으니 JD에 "화장품 경력 필수" 문구 있으면 자동 경고.
처음엔 뺄까 고민했으나 — 지원 못 할 공고를 미리 걸러주는 시간 절약 기능으로 판단.

### 5. 이력서 초안 자동 생성 추가
공고 판단만으로 부족. 괜찮은 공고 찾아도 이력서 맞추는 걸 매번 새로 고민해야 했음.
JD 기반으로 자기소개 / 핵심 경력 3줄 / 지원 동기 초안 자동 생성. 복붙 가능 수준.

### 6. 구조 개편 — 2탭 → 3탭
처음엔 온보딩 / JD 분석기 2탭. 분석 기록이 섞여 복잡했음.
프로필 / 공고 판단 / 지원 현황 3개로 분리하면서 흐름이 명확해짐.

### 7. 다크모드 전환
밝은 베이지 톤(#F8F5EC)에서 판정 배지 구분이 약했음.
어둡게 바꾸니 지원 추천(초록) / 검토 필요(노랑) / 패스(회색)가 확실히 구분됨.

### 8. FIT 점수 체계 도입
정량 점수 추가. (초기엔 전부 100으로 나와 변별력 부족 → 재설계 중)

### 9. 최소 멀티유저 — 기준 개인화 (2026-05)
제작자 1인용·K-뷰티 하드코딩을 걷어내고, 사용자가 자기 기준으로 자기 직무 공고를 판정받게 함.
- **CONFIG·프롬프트 범용화** — `candidate.name/profile`, K-뷰티 페르소나·어필·목표 하드코딩 제거. CONFIG는 범용 폴백 템플릿으로만 남김. (커밋 `28e3a18`)
- **온보딩이 본인 기준 추출** — 이력서에서 커리어 목표(goal) + 3축 판단 기준 정의(직무/환경/성장 def·basis) + 어필 우선순위를 뽑아 프로필에 저장. 결과 화면에서 직접 수정 가능. (커밋 `b62cd7b`)
- **JD 분석이 프로필 기준으로 판정** — 분석 프롬프트가 프로필의 criteria·goal·어필 우선순위를 우선 적용(없으면 CONFIG 폴백). 3축 key/label/비중은 고정 → 판정·보드 로직 안정성 유지. (커밋 `5ea5626`)
- **필수 요건 필터 산업 중립화** — "화장품 경력 필수 감지"를 [내 프로필] 대비 JD 필수 요건 충족 여부(`requirement: mismatch|ok`)로 일반화. 레거시 `cosmetics` 결과도 호환 표시. (커밋 `2069d74`)
- 데이터 분리/동기화는 기존 localStorage 방식 그대로 유지(브라우저별 분리, CLOUD_SYNC=false). 기존 프로필은 재온보딩 전까지 범용 기준으로 폴백.

### 10. 결과 화면 UX 개선 + 바로 쓸 수 있는 수정 문구 (2026-05)
실사용 테스터(은영·이니) 피드백 반영.
- **한눈에 보기 요약 카드** — 점수·판정·한 문장 결론·강점·걸리는점을 맨 위에 압축. FIT SUMMARY 중복 박스 제거, 상세(3축·목표연결)는 아코디언으로 접음. 박스 내 시각적 위계(회사 작게→점수 크게→결론 중간→상세 보조톤). 새 AI 호출 없이 기존 데이터 압축.
- **이력서 헐루시네이션 차단** — 초안 생성이 프로필에 없는 경력·툴을 지어내던 문제(예: 없는 'CVAT' 경력). DRAFT_SYSTEM에 절대 규칙 추가, 'JD 언어 반영' 의미 재정의(없는 경력 채우기 금지).
- **PARSE_FAIL 방어** — 분석 응답 파싱 실패 대응. max_tokens 상향, JSON 규칙 명확화, extractJson 복구 보루 추가.
- **이력서 초안 완성도 개선** — "참고용이 아니라 복붙 제출 가능 수준"으로. 자기소개를 한 문장에 욱여넣지 않고 2~3문장으로(첫 문장 간결+풀어쓰기), 지원 동기 3~5문장(왜 지원+경험 연결+기여), 핵심 경력은 완성 문장. 다문장 렌더(줄바꿈 반영), max_tokens 4000. 환각 금지 강화(분량 늘리려 지어내기 금지, 정직함 우선).
- **초안 구체성 강화** — 두루뭉술한 일반론("총괄했습니다") 대신 프로필에 이미 있는 구체 사실(거래선·국가 수, 계약 규모, 역할, 성과)을 적극 발굴해 '무엇을·어떻게·어떤 결과로'가 드러나게. 지원 동기도 상투구 금지, '내 경험이 있어야만 쓸 수 있는 문장'으로. 단 구체성 = 있는 사실 끌어오기지 없는 숫자·성과 생성이 아님(환각 금지 동시 강화). + 초안 영역에 가벼운 안내 문구("AI 초안이니 본인 경험·말투로 다듬어 쓰길 추천") 추가.
- **"이력서 초안" → "자기소개서 초안"으로 정리** — 이 기능이 돕는 건 이력서(학력·경력 항목, 사용자가 이미 가짐)가 아니라 자기소개서(지원동기·자기소개)임을 명확히. 이름·제목·안내 문구를 자소서에 맞게 변경. 핵심 경험을 개조식 번호 목록 → 서술형 문단으로, 화살표·대시 등 특수기호 제거하고 자연스러운 한국어 문장으로 통일. (환각 금지·구체성은 그대로)
- **환각 강화 — 근거 없는 숫자 디테일 차단** — 초안이 딥해지면서 근거 없는 구체 숫자를 지어내던 문제(예: 임의 기간 "2020년부터 5년간", 언급 없는 "8시간 시차"). 구체적 숫자(기간·연차·시차·금액·인원·비율)는 원본에 명시된 것만 쓰고, 없으면 추측·단정 금지. 불명확하면 숫자 빼고 표현("5년간 추적"→"꾸준히 추적"). "딥함"의 출처를 '있는 사실 충실히'로 못박고 '그럴듯한 디테일 추가'를 금지. (직전 "구체성 강화"가 숫자 채우기를 유발한 부작용 교정)
- **환각 강화 — 근거 없는 고유명사 차단** — 프로필에 없는 유명 브랜드명을 임의로 넣던 문제(예: 운영한 적 없는 "Lancôme·Kiehl's"). 고유명사(회사·브랜드·제품·고객사명)는 원본에 명시된 것만. 없으면 유명 브랜드명 대신 "유럽 프리미엄 브랜드"처럼 일반 표현으로. 숫자·고유명사를 아우르는 '그럴듯한 구체 디테일 지어내기' 패턴 자체를 금지.

> 참고: 개발 중 "바로 쓸 수 있는 수정 문구"(강점/약점 완성 문장 생성) 카드를 잠깐 추가했다가 제거함 — 기존 "이력서 초안"의 핵심경력·지원동기와 내용이 중복돼 사용자가 헷갈렸음. 이력서 관련 산출물은 초안 하나로 통합.
